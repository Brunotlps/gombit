# laravel

The BENCH-1 Laravel + Eloquent ecosystem-context app (issue
[#141](https://github.com/gombit-dev/gombit/issues/141) Phase 4): the same
canonical `/api/projects` CRUD API ([../../docs/schema.md](../../docs/schema.md))
as `../gin-gorm`, `../gombit`, `../django`, and `../rails`, implemented
idiomatically in Laravel — non-Go ecosystem context, not another
framework-tax control.

## Versions (issue #141 §16/§17: pin exact versions)

| Package | Version |
| --- | --- |
| PHP | 8.3 |
| Laravel (`laravel/framework`) | 13.29.0 |
| PostgreSQL driver | `pdo_pgsql` (PHP extension) |
| Web server | nginx + PHP-FPM (see "Production configuration") |

`composer.json` pins the direct dependencies to exact versions;
`composer.lock` (committed) pins every transitive dependency exactly too —
`composer install` reproduces the exact tree. `vendor/` is not committed
(regenerated by `composer install`), the same way `../rails` commits
`Gemfile.lock` but not the gems and `../django` commits `requirements.txt`
but not the venv.

Local development in this repo used `php:8.3` in Docker only because the
host had no PHP installed; the app itself has no Docker dependency.

## Run

```sh
docker compose -f benchmarks/compose.yml up -d postgres
createdb -h 127.0.0.1 -p 55432 -U gombit gombit_bench_laravel   # once

cd benchmarks/apps/laravel
composer install
cp .env.example .env && php artisan key:generate   # .env is gitignored
DATABASE_URL="postgres://gombit:gombit@127.0.0.1:55432/gombit_bench_laravel?sslmode=disable" \
  php artisan migrate --force

# seed (1,000 users, 100,000 projects) — idempotent, truncates first
DATABASE_URL="postgres://gombit:gombit@127.0.0.1:55432/gombit_bench_laravel?sslmode=disable" \
  php artisan db:seed --force

# production: nginx + PHP-FPM (see below) — never `php artisan serve`.
# deploy/php-fpm.conf is a pool config: drop it in your PHP-FPM pool
# directory; deploy/nginx.conf is the server block (document root public/,
# fastcgi to 127.0.0.1:9000). Exact paths are install-specific — this is
# what the local verification used:
cp deploy/php-fpm.conf /usr/local/etc/php-fpm.d/zzz-bench.conf
cp deploy/nginx.conf   /etc/nginx/sites-available/default
php-fpm -D && nginx -g 'daemon off;'
```

### Production configuration (issue #141 §17)

```text
APP_ENV=production
APP_DEBUG=false
nginx + PHP-FPM (deploy/nginx.conf, deploy/php-fpm.conf) — never
`php artisan serve`
```

**This is the traditional PHP deployment, and it differs from the other four
apps in a benchmark-relevant way that the published numbers must be read
with.** A Go binary, Rails' Puma cluster, and Django's gunicorn workers all
keep the framework *booted once* and serve many requests from long-lived
in-process state. Traditional PHP-FPM does not: it **re-bootstraps Laravel on
every request** — there is no persistent in-process app state between
requests. That is how the large majority of Laravel apps actually run in
production, and it is the model this suite deliberately pins for the Laravel
row (rather than Laravel Octane / FrankenPHP's persistent-worker model, which
would be more apples-to-apples with the others but is not the typical
deployment). Reading a Laravel number next to a Go one and concluding "the
language is slower" without accounting for this is the exact misread the
documentation here exists to prevent.

### Database connection pooling (issue #141 §18)

PHP-FPM has no persistent database connection pool the way a single
long-lived process does: each request opens and closes its own PDO
connection (`PDO::ATTR_PERSISTENT` is off by default and left off). The
analog to the pinned "20 max open connections" is therefore the cap on how
many FPM worker processes may run at once, since that bounds the number of
simultaneous Postgres connections. `deploy/php-fpm.conf` sets `pm = static`
with `pm.max_children = 20` — at most 20 workers, hence at most 20
concurrent connections, matching the ceiling every other implementation
pins.

### Request logging (issue #141 §19)

Unlike `../rails` (whose scaffold default logs a line per request and had to
be quieted on review), Laravel does **not** log per-request by default —
there is no access-log middleware in the default stack. `LOG_LEVEL=warning`
(`.env.example`) keeps the app log to warnings/errors, and
`deploy/nginx.conf` sets `access_log off` so nginx does not write a line per
request either. Errors are still logged.

## Test

```sh
docker compose -f benchmarks/compose.yml up -d postgres
createdb -h 127.0.0.1 -p 55432 -U gombit gombit_bench_laravel_test   # once —
  # a separate database: RefreshDatabase runs `migrate:fresh` (drops all
  # tables), so it must not point at the seeded dev/prod database
cd benchmarks/apps/laravel
DATABASE_URL="postgres://gombit:gombit@127.0.0.1:55432/gombit_bench_laravel_test?sslmode=disable" \
  DB_CONNECTION=pgsql php artisan test
```

Tests run against real PostgreSQL (`phpunit.xml` pins `DB_CONNECTION=pgsql`;
`DATABASE_URL` comes from the environment). The canonical schema is
Postgres-specific (TEXT columns, TIMESTAMPTZ, a real FK), so the scaffold's
default sqlite `:memory:` was replaced — sqlite would silently diverge.

Covers the same contract the four sibling suites pin: full
create/get/update/delete/404/validation-failure round trip, including a
foreign-key violation rejected as `422` `validation_error` (leaning on the
FK, like `../gin-gorm`/`../django`, not an extra existence query); blank-name
rejection on create and update (see "Update-name validation" below); the
present-null `description` contract (`422`, matching `../rails`/`../django` —
see below); whitespace and empty-string preservation for `description` (see
"Trimming" below); list pagination/ordering; a query-count guard (3 for a
non-empty page, 2 for empty — matching `../gin-gorm`'s pinned shape via
`with('owner')`); the seed content formulas' determinism and round-robin
math (ported by hand); the seed contract's DB-backed idempotency; and the
schema contract itself (`SchemaContractTest`, querying
`information_schema`/`pg_constraint` directly rather than trusting a one-time
`psql \d` — the DB-backed guard `../rails` added after its own review). Every
rejection test asserts the D10 `error.code`, not just the HTTP status.

## Schema and validation notes

Verified against real PostgreSQL (`psql \d`, and `SchemaContractTest` in CI)
against [../../docs/schema.md](../../docs/schema.md):

- `$table->text()`, not the migration-generator default `$table->string()`
  (`VARCHAR(255)`), for `email`/`name`/`description`: the canonical columns
  are unbounded `TEXT`.
- `$table->foreign('owner_id')` with no `->onDelete()`/deferrable option,
  leaving Postgres's own `NO ACTION`, immediately-checked default — matching
  the canonical FK. `../django`'s ORM instead always emits `DEFERRABLE
  INITIALLY DEFERRED` and needed a follow-up migration; Eloquent, like GORM
  and ActiveRecord, does not.
- **`$table->timestampTz('...', 6)`**: Laravel's `timestampTz` defaults to
  **precision 0** (whole seconds), which would truncate `created_at`/
  `updated_at` to the second while every sibling stores microseconds.
  Passing precision `6` matches. The models also set `$dateFormat = 'Y-m-d
  H:i:s.uP'` because Eloquent's Postgres grammar otherwise *writes*
  timestamps at whole-second precision, so an API-created row would come
  back as `.000000` even against a microsecond column.
- **Laravel's global `TrimStrings` and `ConvertEmptyStringsToNull`
  middleware are removed** (`bootstrap/app.php`). Both silently rewrite
  client input before any controller sees it: `TrimStrings` would strip the
  leading/trailing whitespace the canonical contract requires be stored
  byte-for-byte (the exact issue `../django`'s review caught in its
  serializer), and `ConvertEmptyStringsToNull` would turn a legitimate
  `description: ""` into `null` (which this app then rejects). Removing them
  is what makes `description: "  x  "` round-trip and `description: ""` stay
  `""`.
- **Present-null `description`** (`{"description": null}`, valid JSON,
  distinct from an omitted key) is rejected as `422` `validation_error` on
  both create and update — matching `../rails`/`../django`'s settled
  contract. The `string` validation rule fails on an explicit null; an
  omitted key defaults to `""` on create and leaves the column unchanged on
  update. (`../gin-gorm` instead treats null as "not provided"; the siblings
  genuinely disagree on this underspecified corner, and this app takes the
  reject-null side uniformly, the way `../rails` did.)
- **Update-name validation** uses `sometimes|required|...`, not just
  `sometimes|...`: Laravel skips the non-implicit `regex:/\S/` rule on an
  empty string, so `PATCH {"name": ""}` would otherwise pass validation and
  blank the name. `required` (an implicit rule) rejects `""`/`null` when the
  key is present, while `sometimes` still lets an omitted key through
  untouched.
- The N+1 guard is **3 queries for a non-empty page** (`COUNT`, the page
  `SELECT`, one batched `select * from users where id in (...)` from
  `with('owner')`) and **2 for an empty page** — matching `../gin-gorm`'s
  pinned shape exactly (`with`, not a JOIN, so no documented deviation is
  needed the way `../django`'s 2-query `select_related` JOIN did).
